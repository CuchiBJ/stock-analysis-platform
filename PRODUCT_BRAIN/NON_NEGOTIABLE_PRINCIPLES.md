# NON-NEGOTIABLE PRINCIPLES
## Immutable Rules That Define Product Identity

**Purpose**: These principles are the bedrock of the product. They cannot be compromised, diluted, or ignored without losing product identity.

---

## PRINCIPLE 1: TRANSITIONS DOMINATE OVER STATIC METRICS

**The principle**:
- Change is more important than state
- Momentum shifts are more valuable than absolute levels
- Deterioration patterns matter as much as improvement patterns
- Rate of change > current value

**Why it matters**:
- Static metrics without context are noise
- Institutions trade on changes in sponsorship
- Momentum is about acceleration, not speed
- Setup quality depends on transition quality

**Implementation**:
- All metrics must have temporal context
- Rate of change calculations are mandatory
- Deterioration detection is first-class
- Transition states are primary signals

**Anti-patterns**:
- Presenting RSI=50 without showing it was 70 yesterday
- Showing P/E ratio without showing trend
- Static filters without time decay
- Snapshot-only displays

**Examples**:
✅ "RSI deteriorated from 70 to 50 in 5 days"
✅ "Sponsorship score declined from 8 to 6"
❌ "Current RSI: 50"
❌ "P/E Ratio: 25"

---

## PRINCIPLE 2: SCARCITY IS SIGNAL

**The principle**:
- Quality setups are rare by design
- If everything looks good, nothing is
- Filtering is more important than finding
- Less is more in institutional trading

**Why it matters**:
- Institutional edge comes from selectivity
- Retail traders over-trade; institutions under-trade
- Cognitive load must be managed
- Scarcity creates confidence

**Implementation**:
- Default filters must be aggressive
- Only top-tier setups pass through
- Quality thresholds are high
- "No setups today" is a valid state

**Anti-patterns**:
- Showing 100+ stocks in results
- "Expand your search" suggestions
- Lowering filters to show more results
- Celebrating result quantity

**Examples**:
✅ "3 high-quality setups today"
✅ "No setups meeting criteria"
❌ "50 stocks matching your filters"
❌ "Try relaxing filters to see more"

---

## PRINCIPLE 3: CONTEXT COMPRESSION IS MANDATORY

**The principle**:
- Raw data must be synthesized
- Information must be pre-digested
- Narrative must be constructed
- Cognitive load must be reduced

**Why it matters**:
- Traders operate under time pressure
- Information overload kills performance
- Professional tools synthesize, don't expose
- Context enables faster decisions

**Implementation**:
- Every display must have narrative
- Metrics must be grouped by meaning
- Visual hierarchy must guide attention
- Key signals must be immediately visible

**Anti-patterns**:
- Raw data tables without synthesis
- Requiring users to interpret metrics
- Equal visual weight for all information
- "Here's the data, figure it out"

**Examples**:
✅ "Setup deteriorating: sponsorship down, volume drying up"
✅ "Strong continuation: all signals aligned"
❌ Table with 20 metrics, no narrative
❌ "Here are the indicators, interpret them yourself"

---

## PRINCIPLE 4: DETERIORATION IS FIRST-CLASS INFORMATION

**The principle**:
- Decay patterns are as important as growth patterns
- Setup failure must be detected early
- Negative transitions signal risk
- Deterioration velocity matters

**Why it matters**:
- Loss prevention is critical
- Early exit signals preserve capital
- Institutions monitor sponsorship decay
- Momentum reversal starts with deterioration

**Implementation**:
- Deterioration metrics are mandatory
- Negative transitions are highlighted
- Decay velocity is calculated
- Deterioration triggers alerts

**Anti-patterns**:
- Only showing positive signals
- Hiding deterioration to be "positive"
- Treating all changes equally
- Ignoring negative momentum

**Examples**:
✅ "Sponsorship deteriorating at -0.5/day"
✅ "Volume decay detected, setup weakening"
❌ Only green indicators shown
❌ "All metrics look good" (when deteriorating)

---

## PRINCIPLE 5: REGIME AFFECTS EVERYTHING

**The principle**:
- Market regime changes all rules
- Bull/bear/volatile regimes require different approaches
- Setup effectiveness varies by regime
- Regime awareness is mandatory

**Why it matters**:
- What works in bull markets fails in bear markets
- Institutions adjust strategy by regime
- Ignoring regime is fatal
- Regime is the master context

**Implementation**:
- Regime detection is mandatory
- Setup rules vary by regime
- Visual cues indicate current regime
- Regime changes trigger alerts

**Anti-patterns**:
- Same rules regardless of market
- Ignoring volatility regime
- Treating all market conditions equally
- No regime indication in UI

**Examples**:
✅ "Bull regime: continuation setups favored"
✅ "Bear regime: only quality setups shown"
❌ "Here are the best setups" (no regime context)
❌ Same filters in all markets

## PRINCIPLE 6: OPERATIONAL CLARITY BEATS FEATURE RICHNESS

**The principle**:
- Clear workflow > many features
- Fewer, better tools > many mediocre tools
- Operational speed > feature count
- Workflow continuity > feature variety

**Why it matters**:
- Feature bloat creates confusion
- Professional tools are specialized
- Speed is critical in trading
- Clarity reduces cognitive load

**Implementation**:
- Each feature must earn its place
- Workflow must be linear and clear
- Redundant features are removed
- Complexity is actively resisted

**Anti-patterns**:
- Feature lists as selling points
- "Me too" feature additions
- Multiple ways to do the same thing
- Features that require training

**Examples**:
✅ Single, clear workflow for setup analysis
✅ One way to view setups, done well
❌ "We have 50+ features!"
❌ Three different screener interfaces

---

## PRINCIPLE 7: INTERPRETABILITY OVER PREDICTION

**The principle**:
- Systems must be explainable
- Rules must be transparent
- Users must understand why
- Black boxes are unacceptable

**Why it matters**:
- Traders need confidence in signals
- Debugging requires transparency
- Regulatory compliance demands explainability
- Professional tools don't hide logic

**Implementation**:
- All rules are explicit and documented
- Signal rationale is always shown
- Metric calculations are transparent
- No black-box ML for core logic

**Anti-patterns**:
- "AI says buy" without explanation
- Hidden recommendation engines
- Opaque scoring systems
- Confidence scores without rationale

**Examples**:
✅ "Setup flagged because: sponsorship up, volume expanding"
✅ "Score: 8/10 (based on X, Y, Z metrics)"
❌ "AI recommendation: BUY (confidence: 87%)"
❌ "Trust the algorithm"

---

## PRINCIPLE 8: VISUAL HIERARCHY MUST REFLECT URGENCY

**The principle**:
- Important information must be prominent
- Urgent signals must be visually distinct
- Attention must be guided, not scattered
- Visual weight must match information value

**Why it matters**:
- Traders scan for critical information
- Poor hierarchy wastes time
- Urgent signals get lost in noise
- Professional tools guide attention

**Implementation**:
- Critical signals use highest contrast
- Deterioration signals are visually distinct
- Information architecture is hierarchical
- Visual design is intentional, not decorative

**Anti-patterns**:
- Equal visual weight for all information
- Critical signals buried in detail
- Decoration that distracts from signal
- No visual hierarchy

**Examples**:
✅ Deterioration alerts in red, prominent
✅ Setup quality score large and centered
❌ All metrics same size and color
❌ Critical information in small font

## PRINCIPLE 9: INSTITUTIONAL SPONSORSHIP IS PRIMARY SIGNAL

**The principle**:
- Smart money flows drive price
- Institutional activity is the edge
- Sponsorship tracking is mandatory
- Retail sentiment is noise

**Why it matters**:
- Institutions move markets
- Retail follows, doesn't lead
- Sponsorship indicates conviction
- Smart money flow is the signal

**Implementation**:
- Sponsorship metrics are core
- Institutional activity is tracked
- Smart money flow is calculated
- Sponsorship changes trigger alerts

**Anti-patterns**:
- Retail sentiment as primary signal
- Social media indicators
- "Most popular" rankings
- Ignoring institutional activity

**Examples**:
✅ "Institutional sponsorship increasing"
✅ "Smart money flow positive"
❌ "Retail sentiment bullish"
❌ "Trending on social media"

---

## PRINCIPLE 10: WORKFLOW > ANALYTICS

**The principle**:
- The system must enable action, not just show data
- Workflow continuity is paramount
- Analysis paralysis must be prevented
- Operational speed is the metric

**Why it matters**:
- Trading is operational, not analytical
- Speed of decision matters
- Endless analysis kills performance
- Professional tools enable action

**Implementation**:
- Clear, linear workflow
- Minimal friction between steps
- Action-oriented design
- Reduce analysis to essentials

**Anti-patterns**:
- Endless drill-down interfaces
- Analysis for analysis sake
- Multiple parallel workflows
- No clear path to action

**Examples**:
✅ Scan → Analyze → Decide workflow
✅ Clear next action at each step
❌ "Explore the data" interfaces
❌ No clear workflow path

## PRINCIPLE ENFORCEMENT

**For Developers**:
1. Every feature must align with these principles
2. Violations must be caught in design review
3. Document how each principle is satisfied
4. Reject features that violate principles

**For LLMs**:
1. Check all suggestions against these principles
2. Explicitly cite relevant principles
3. Reject suggestions that violate principles
4. Redirect to principle-aligned alternatives

**For Product Decisions**:
1. Apply principles as decision filter
2. Principles override user requests
3. Document principle violations as rejections
4. Maintain principle consistency

---

## PRINCIPLE CONFLICT RESOLUTION

**When principles conflict**:
1. Principle 1 (Transitions) and Principle 4 (Deterioration) take precedence
2. Principle 5 (Regime) affects all other principles
3. Principle 2 (Scarcity) overrides feature requests
4. Document the resolution rationale

**Example conflict**:
- User wants more results (violates Principle 2: Scarcity)
- Resolution: Reject, maintain scarcity
